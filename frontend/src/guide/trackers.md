# Трекеры

Здесь задаётся, откуда панель берёт задачи трекеров: где у каждого проекта лежат задачи и чем панель ходит на серверы трекеров. По этому [«Бэклог»](backlog.md) показывает открытые задачи трекера, а Чудо-Юдо по описанию трекера находит, куда ходить, когда ищет задачи и переносит в трекер записи бэклога. Ключи из «Серверов трекеров» нужны только панели: Чудо-Юдо ходит в YouTrack подключением самого Claude Code, а в GitHub — программой gh. Сами задачи здесь не показываются: они живут на вкладке «Задачи трекера» «Бэклога».

## Как читать экран

Сверху — проекты и их трекеры, под ними — список «Серверы трекеров».

Слева стоят все проекты из списка баз. У каждого — метка трекера и имя проекта: «GH» у GitHub, «YT» у YouTrack, «JI» у Jira, «GL» у GitLab; пунктирный квадрат — у проекта без трекера и у проекта, чья база не читается. Красная точка справа значит, что у проекта что-то сломано. Выбранный проект выделен так же, как раздел в полосе слева, а справа видно всё о нём.

| Строка справа | Что в ней |
|---|---|
| Вид трекера | GitHub, GitLab, Jira или YouTrack. |
| Адрес сервера | Сервер трекера. |
| Проект | Репозиторий GitHub или проект на сервере. |
| Фильтр | Только у GitHub и YouTrack: строка поиска трекера, которой «Бэклог» отбирает задачи. «нет, берутся все задачи проекта» — фильтра нет. |
| Ключ к серверу | Чем панель читает задачи: у GitHub — «вход через gh», у YouTrack — «ключ пользователя» с логином или красное «нет ключа к этому серверу», если сервера проекта нет в «Серверах трекеров». Рядом с ним кнопка `Добавить`: она переводит к «Серверам трекеров», подставляет адрес сервера проекта и ставит курсор в поле «Ключ». |

Если описание трекера записано не так, как требует кит, над строками стоит красная плашка с тем, что именно не так. У проекта без трекера справа — «В этом проекте нет трекера» и крупная кнопка `Завести трекер`.

Почти всё здесь хранится в базе знаний: описание трекера проекта пишется в базу и уходит с ней на сервер, поэтому его видят и коллеги. Ключи к серверам — исключение: они хранятся только на этом компьютере.

### Серверы трекеров

Адреса серверов трекеров задач и ваши ключи доступа к ним. Нужны для трекеров, в которые вы не входите своей программой, например для YouTrack. У каждого сервера в списке написано, чей это ключ: «ключ пользователя» и логин.

Сервер добавляют полями «Адрес сервера» и «Ключ»; ключ — это постоянный токен, который выпускают в профиле трекера. После `Добавить` панель проверяет ключ на самом сервере и сохраняет его, только если сервер назвал владельца ключа. Если ключ опечатан, отозван или у владельца нет прав, причина появится сразу под полем, а не потом в «Бэклоге».

Ключ хранится зашифрованным и только на этом компьютере. Панель не показывает его никогда, даже вам: заменить можно, посмотреть нельзя.

### Окно «Трекер проекта»

Кнопки `Завести трекер` и `Изменить` справа открывают одно и то же окно «Трекер проекта» — устроено оно так же, как окно исполнителя. В окне все поля описания:

- вид трекера — GitHub, GitLab, Jira или YouTrack;
- «Адрес сервера» и «Проект»;
- у GitHub и YouTrack — необязательное поле «Фильтр»: строка поиска самого трекера, например `State: {To Do}` у YouTrack или `label:bug` у GitHub. С ним «Бэклог» показывает только подходящие задачи; пустое поле — все открытые задачи проекта. Только свои задачи даёт фильтр `assignee:@me` у GitHub или `Assignee: me` у YouTrack. У Jira и GitLab фильтра нет;
- пять разделов описания — «Где задачи», «Показ бэклога», «Взятие задачи», «Задача закрыта», «Вынос записи бэклога».

Все поля правятся руками. У существующего трекера изменённое поле помечено «изменено», а прежнее значение видно зачёркнутым под подписью.

Кнопка `Сохранить` записывает описание в базу и отправляет базу на сервер, после чего окно закрывается. Для GitHub и YouTrack панель сначала читает задачи проекта на сервере — внизу окна написано «Панель читает задачи проекта…», — и пишет описание, только если они прочитались; если нет, причина встаёт под нужным полем. Фильтр, который YouTrack не принял, не записывается, а причина встаёт под полем «Фильтр». Фильтр, по которому сейчас задач нет, записывается: об этом скажет «Бэклог». GitHub ошибочный фильтр не отвергает, а просто ничего по нему не находит. Jira и GitLab панель не проверяет и пишет описание сразу, о чём предупреждает строкой внизу окна. Пока правок нет, `Сохранить` приглушена.

### Переписка с Чудо-Юдо

Описание можно не писать руками, а поручить Чудо-Юдо: кнопка `Переписать с Чудо-Юдо` в окне трекера (у нового — `Завести с Чудо-Юдо`) открывает поверх окно «Трекер проекта с Чудо-Юдо».

На вкладке «Переписка» вы своими словами говорите, где задачи проекта и что с ними делать, а Чудо-Юдо предлагает описание целиком. Для начала под словом «Например» стоят готовые просьбы. Реплику можно надиктовать кнопкой микрофона слева внизу. Пока Чудо-Юдо отвечает, видно, сколько прошло времени и что он делает. С каждой репликой уходит описание, каким оно стоит в полях окна трекера, поэтому ваши правки руками он видит.

На вкладке «Изменения» его предложение сверено с полями окна трекера: изменённое помечено «изменено», прежнее значение зачёркнуто. Если ответ что-то поменял, на вкладке загорается точка. Кнопка `Принять правки` кладёт предложение в поля окна трекера и закрывает переписку. В базу оно ещё не записано: над полями встаёт строка «Правки Чудо-Юдо приняты» со ссылкой «вернуть как было», а записывает `Сохранить`.

Разговор живёт в панели, а не в окне: закрытое окно его не прерывает, а в шапке панели появится полоса просьб. О ней рассказывает страница [«Шапка панели»](header.md). Переписка о трекере идёт одна на все проекты.

## Что можно сделать

- **Щелчок по проекту слева** Показывает справа его трекер.
- **`Завести трекер` и `Изменить`** Открывают окно «Трекер проекта» для описания трекера проекта.
- **`Переписать с Чудо-Юдо`** В окне трекера открывает переписку, в которой Чудо-Юдо пишет описание.
- **`Сохранить`** Проверяет трекер, записывает описание в базу и отправляет базу на сервер.
- **`Удалить` у трекера** После подтверждения убирает описание трекера из базы и отправляет базу на сервер. «Бэклог» перестанет показывать задачи этого трекера.
- **`Добавить` у ключа проекта** Переводит к «Серверам трекеров» с подставленным адресом сервера проекта.
- **`Добавить` сервер** Проверяет ключ на сервере и сохраняет сервер с ключом.
- **`Заменить ключ`** Открывает под строкой сервера поле «Новый ключ». Новый ключ проходит ту же проверку на сервере, что и при добавлении.
- **`Удалить` у сервера** Убирает сервер вместе с ключом после подтверждения. Чтобы снова читать задачи с этого сервера, ключ придётся ввести заново.

## Частые случаи

### Задачи трекера не видны в «Бэклоге»

Выберите проект слева. Если у него нет трекера, заведите его кнопкой `Завести трекер`. Если справа красная плашка, нажмите `Изменить` и поправьте названное. Если трекер на YouTrack и в строке «Ключ к серверу» написано «нет ключа к этому серверу», нажмите рядом `Добавить`, вставьте ключ в поле «Ключ» и нажмите `Добавить` у формы сервера: ключ сохранится, когда сервер его примет.

Красные строки «Бэклога» ведут сюда ссылкой «Трекеры»: строка о поломке описания сразу выбирает нужный проект, а строка о ключе показывает «Серверы трекеров».

### «База не отправлена на сервер»

Описание трекера записано на этом компьютере, но на сервер не ушло. Окно показывает, что ответил кит: его слова называют причину. Пока базу не отправят, коллеги этой правки не увидят.

## Чего панель не даст сделать

- **Сохранить ключ, который сервер не принял.** Ключ сохраняется, только когда сервер назвал его владельца. Иначе ошибка всплыла бы потом, в «Бэклоге».
- **Показать сохранённый ключ.** Ключ не выходит из панели ни в каком виде. Его можно только заменить.
- **Поменять адрес сервера.** Сервер с другим адресом добавляют заново, а прежний удаляют.
- **Удалить трекер, по которому идёт задача.** Пока в какой-то копии идёт задача из этого трекера, `Удалить` приглушена, а подсказка называет копию и задачу.
- **Править трекер базы нового формата.** Если кит перевёл базу на формат, которого эта версия панели не знает, кнопки трекера приглушены. Поможет обновление панели, когда выйдет выпуск под новый формат.
- **Записать описание, не проверив трекер.** У GitHub и YouTrack описание пишется, только когда задачи проекта прочитались: иначе «Бэклог» узнал бы о поломке последним.

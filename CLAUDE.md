# agents-kit-web

Веб-панель оператора над базами знаний agents-kit.

## Структура

- `backend/` — .NET 10 minimal API (`AgentsKitWeb.slnx`): `src/AgentsKitWeb.Api`, тесты в `tests/AgentsKitWeb.Api.Tests`.
- `frontend/` — React + TypeScript на Vite. Фронт ходит на относительный `/api`, dev-сервер Vite проксирует его на API.
- `design/` — временный набросок, не спецификация.

## Запуск

```sh
# API на http://localhost:5078
dotnet run --project backend/src/AgentsKitWeb.Api --launch-profile http

# фронт на http://localhost:5173
cd frontend
npm install
npm run dev
```

## Номер версии

Номер версии панели — `version.txt`. Его поднимает агент в ветке задачи своим коммитом перед слиянием в dev — на каждое
слияние, в том числе инструкции, служебной мелочи или быстрой починки: по номеру выходит сборка и панель узнаёт, что
вышло новое. Пока панель в разработке, номер — 0.X.X, и первое число не трогается: сломано привычное или добавлено
новое — второе число, починено — третье. Выкладка dev в master переносит номер как есть.

Забытый номер ловят хуки git из `.githooks`: слияние в dev не проходит, если номер не вырос против dev, а отправка dev
и master — если он не вырос против того, что уже лежит на сервере. Хуки слияния git зовёт, только когда создаёт коммит
слияния, поэтому слияние в dev настроено всегда его создавать; `--ff-only` в команде, которым dev подтягивают к серверу,
эту настройку перебивает. Обе настройки включаются один раз на клон и действуют во всех его рабочих копиях:

```sh
git config core.hooksPath .githooks
git config branch.dev.mergeOptions --no-ff
```

Хуки каждая копия берёт из своей выкачанной ветки: в копии на ветке, отрезанной раньше, чем в dev появился
`.githooks`, их нет, пока она не подтянет dev.

## Поставленная панель

Для постоянной работы панель ставится готовой сборкой с GitHub и работает на http://localhost:5080 — отдельно
от dev-запуска. Сборку выпускает `.github/workflows/release.yml`, когда код приходит в канал: в master — выпуск
`v<номер>`, в dev — предварительный `v<номер>-dev`; номер — `version.txt`, и повтор номера в канале валит сборку.
Архив — панель со средой .NET внутри, собранный фронт в `wwwroot`, `build.json` о сборке и скрипты `deploy.ps1`
и `update.ps1`. Перечень задач выпуска считает `scripts/release-notes.ps1`.

Кнопка «Обновить» в «Настройках» запускает `update.ps1` из своей сборки: он скачивает выпуск канала и ставит его
`deploy.ps1` — останавливает панель, подменяет каталог `%LOCALAPPDATA%\agents-kit-web\app`, регистрирует или обновляет
задачу Планировщика заданий `agents-kit-web panel` (при входе текущего пользователя, без прав администратора)
и запускает панель. Панель читает тот же `bases.json` из `%APPDATA%\agents-kit-web`, что и dev-API.

Собрать и поставить панель из исходников — для разработки и приёмки ветки:

```powershell
pwsh -NoProfile -File scripts/publish.ps1
```

Скрипт собирает master (или `-Ref`) во временном git worktree тем же `scripts/build.ps1`, что и выпуск, — рабочая копия
и её ветка не трогаются, — и ставит через `deploy.ps1`; параметры `-Ref`, `-Target`, `-Port`, `-TaskName` меняют ref,
каталог, порт и задачу. Поставленная так панель обновляется кнопкой, как любая, — готовой сборкой своего канала.

Поставленная панель собрана из master и правок ветки задачи не содержит: приёмку смотрят на dev-панели.

### На другом компьютере

Панель ставят одной строкой в Windows PowerShell:

```powershell
iex ((irm https://raw.githubusercontent.com/t8nax/agents-kit-web/master/scripts/install.ps1).TrimStart([char]0xFEFF))
```

`scripts/install.ps1` сначала проверяет, что на компьютере есть Claude Code со входом в аккаунт; нет — называет, что
сделать, и больше ничего не делает. Затем ставит через winget git и PowerShell 7, если их нет (Windows может спросить
разрешение), ставит кит из магазина плагинов Claude Code, если кита нет, скачивает готовую сборку последнего выпуска канала и ставит её `deploy.ps1`
из сборки. Список баз и путь к киту не переносятся — их задают в «Настройках» на месте. Параметры `-Releases`,
`-Channel`, `-Tag`, `-Target`, `-Port`, `-TaskName` — для запуска файлом.

## Песочница

Чтобы ломать панель, не задевая живые базы, есть одноразовая песочница: выдуманные базы и копии, заглушки
кита и агента, свой каталог и порт у каждой рабочей копии. Собирается под задачу: в неё кладутся только
названные куски — здоровый проект, каждая нарочно сломанная база отдельно — и свой кусок задачи, если
нужного случая в готовых нет. Без кусков сборка отказывает и перечисляет их.

```powershell
pwsh -NoProfile -File scripts/sandbox.ps1 -Pieces house,quirks
```

Какие куски бывают, как дописать свой, что в них сломано заранее и как переключать режимы заглушек —
`scripts/sandbox.md`.
